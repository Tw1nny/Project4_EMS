# EMS — сервис управления email-рассылками

Курсовой проект на Django: пользователи ведут базу клиентов, пишут
сообщения, создают рассылки с периодом отправки и запускают их вручную.
Каждая попытка отправки сохраняется, по ним строится статистика.
Менеджеры видят данные всех пользователей, могут отключать рассылки
и блокировать пользователей.

## Возможности

- Клиенты (получатели), сообщения и рассылки — полный CRUD.
- Статус рассылки («Создана», «Запущена», «Завершена») вычисляется по
  текущему времени методом `Mailing.update_status()` при каждом просмотре.
- Отправка по требованию — кнопкой на странице рассылки или командой
  `python manage.py send_mailing`. Отправка разрешена только между
  `start_time` и `end_time`, иначе показывается ошибка.
- Попытки отправки («Успешно» / «Не успешно» + ответ почтового сервера)
  сохраняются одним запросом через `bulk_create`.
- Регистрация с подтверждением email, вход и выход, восстановление пароля.
- Роли: пользователь и менеджер.
- Статистика по своим рассылкам.
- Кеширование: серверное (Redis) и клиентское (HTTP-заголовки).

## Стек

## Установка и запуск

1. Создайте и активируйте виртуальное окружение, установите зависимости:

   ```bash
   pip install -r requirements.txt
   ```

2. Скопируйте `.env.example` в `.env` и заполните: `SECRET_KEY`, данные
   PostgreSQL, при необходимости почту и Redis. Ключ можно сгенерировать:

   ```bash
   python -c "from django.core.management.utils import get_random_secret_key as k; print(k())"
   ```

3. Создайте базу данных:

   ```bash
   psql -U postgres -c "CREATE DATABASE ems_db;"
   ```

4. Примените миграции, создайте группу менеджеров и администратора:

   ```bash
   python manage.py migrate
   python manage.py create_groups
   python manage.py createsuperuser
   ```

5. Запустите сервер: `python manage.py runserver` → http://127.0.0.1:8000/

Чтобы сделать пользователя менеджером: админка → Пользователи →
пользователь → поле «Группы» → «Менеджеры».

### Почта

По умолчанию письма (рассылки, подтверждение регистрации, восстановление
пароля) печатаются в консоль `runserver` — ссылку подтверждения можно
скопировать оттуда. Для настоящей отправки заполните блок «Почта» в `.env`.

### Redis

Серверный кеш хранится в Redis (`REDIS_URL`, по умолчанию база 2).
Redis под Windows ставится через WSL (`sudo apt install redis-server`),
Docker (`docker run -d -p 6379:6379 redis`) или Memurai. Без Redis
укажите в `.env` `CACHE_ENABLED=False` — проект будет работать без кеша.

## Роли и права

| Действие | Пользователь | Менеджер |
|---|---|---|
| Свои клиенты, сообщения, рассылки: создание, просмотр, изменение, удаление | да | да |
| Просмотр клиентов, сообщений и рассылок всех пользователей | нет | да |
| Изменение и удаление чужих данных | нет | нет (403) |
| Запуск рассылки | только своей | только своей |
| Статистика по своим рассылкам | да | да |
| Список пользователей, блокировка | нет | да |
| Отключение рассылок | нет | да |

Права менеджера — кастомные права моделей (`can_view_all_recipients`,
`can_view_all_messages`, `can_view_all_mailings`, `can_disable_mailing`,
`can_view_users`, `can_block_users`), выдаются группе «Менеджеры»
командой `create_groups`.

## Отправка из командной строки

```bash
python manage.py send_mailing 5       # рассылка №5
python manage.py send_mailing --all   # все рассылки, которые сейчас можно отправить
```

## Кеширование

- **Серверное (Redis), низкоуровневое**, в `mailings/services.py`:
  показатели главной страницы (60 секунд), списки клиентов, сообщений,
  рассылок и статистика (15 минут). Когда данные меняются, сигналы
  сбрасывают нужный раздел кеша, поэтому изменения видны сразу.
- **Клиентское**: `ConditionalGetMiddleware` (ETag, ответ 304 Not
  Modified) и заголовок `Cache-Control: private, max-age=60` на главной.

## Соответствие критериям

| Критерий | Где реализовано |
|---|---|
| Модели и поля по заданию | `mailings/models.py` — `Recipient`, `Message`, `Mailing`, `MailingAttempt` |
| Письмо отправляется каждому получателю рассылки | `mailings/services.py` → `send_mailing()` |
| Отправка только между `start_time` и `end_time`, иначе ошибка | `send_mailing()` → `MailingSendError`, сообщение на странице рассылки |
| Попытки сохраняются через batch | `MailingAttempt.objects.bulk_create(...)` в `send_mailing()` |
| Регистрация с подтверждением email, вход, выход, восстановление пароля | `users/views.py`, `users/urls.py` |
| Данные сохраняются в БД | PostgreSQL, миграции `users` и `mailings` |
| Доступ по ролям | `mailings/views.py` (OwnerQuerysetMixin, OwnerRequiredMixin, права менеджера), `users/views.py` |
| Данные берутся из кеша | `mailings/services.py` → `get_home_stats`, `get_recipients`, `get_messages`, `get_mailings`, `get_user_stats` |
